The intuition for a classifier

Imagine a scatter of red and green points on a plane, and the task of drawing a single straight line that separates the two classes. There are infinitely many lines that could do this — so which one is "best"?

Measuring how wrong a line is

For any candidate line, we can count how many points it misclassifies. A perfect separating line misclassifies nothing, so its error is 0. A line that puts a single red point on the wrong side, out of 100 total points, has an error of 1%.

error = (number of misclassified points ÷ total points) × 100

Repeating this error calculation for every possible line produces an error curve — a plot where each point represents one candidate line, and its height represents that line's error.

Minimum error, best line. The line sitting at the lowest point of this error curve is the best separating line. This error function is also called the loss function or cost function — ideally it should reach 0.

If we know the shape of this error function, the problem reduces to: find the input that makes the function smallest, then read off the corresponding line (in practice, the line's defining weight vector).

Why brute-force search fails

Without calculus, the obvious strategy is to try every candidate line one at a time — a linear search — and keep the one with the lowest error.

Suppose a line in 2 features is defined by weights w₁, w₂, and w₀, and each weight is tested from −10 to +10 in steps of 0.1. That's 201 values per weight. With 3 weights, the total number of combinations is 201³.

At 3 weights the search finishes in about 8 seconds. Add one dimension (a 3D plane instead of a 2D line) and it balloons to ≈27 minutes. Add one more and it's ≈91 hours. This exponential blow-up — and the fact that the right answer is only guaranteed if it happens to fall inside the tested range — makes brute force useless for real datasets with many features.

Introducing gradient descent

Gradient descent is the smarter alternative: instead of testing every possibility, it searches for an approximately correct solution by following the slope of the error function downhill.

To understand gradient descent properly, four concepts need to be built up from the ground up:

The foundation: what it means for a function to behave predictably as its input changes, and when a slope can even be defined.
Built on limits — the derivative measures the instantaneous rate of change of a function, visualised as the slope of a tangent line.
Using derivatives to find where a one-input function is at its minimum or maximum.
Extending the same ideas to functions of many weights at once — exactly the setting a real classifier lives in.

These topics build bottom-up: basics first, advanced concepts after.

Classification, formally

A dataset with d features and a binary target is written as:

D = { (xᵢ, yᵢ) : xᵢ ∈ ℝᵈ, yᵢ ∈ {1, −1} }ⁿᵢ₌₁

The goal is to find a function f(x) that, given a feature vector x̄, predicts the class it belongs to. The predicted value is written ŷᵢ (or yᵢ′); ideally ŷᵢ = yᵢ, the true label.

One such classifier is the perceptron, which checks the sign of:

wᵢᵀx + w₀

to decide which half-space a point falls into.

Distance and the gain function

Rather than just counting errors, a richer measure rewards classifiers whose correctly-classified points sit far from the decision boundary — this is the gain function.

g(x̄ᵢ, yᵢ, w̄, w₀) = ( (wᵀxᵢ + w₀) / ‖w‖ ) · yᵢ

A high gain value means the classifier is good: most points sit far from the boundary. Since loss is the opposite of gain, a high gain corresponds to a low loss. The optimal parameters w̄* and w₀* are the ones that maximise the gain function over the whole dataset:

argmaxw̄, w₀ G(D, w̄, w₀)

Note that it is the parameters at the maximum we care about, not the maximum value itself.

Why sum distances, not multiply them

Given two candidate ways to combine per-point gains across the dataset — summing them, or multiplying them — summing is correct. Consider a point sitting exactly on the boundary line: its distance is 0. If distances were multiplied, that single zero would collapse the entire product to zero regardless of how well every other point is classified. Summing avoids this flaw.

What is a function?

Writing f(x) = y describes f(x) as a mapping between an input x and an output y.

TermMeaning
DomainAll x-axis values the function is allowed to take (e.g. log(x) is undefined for negative numbers, so negative values are excluded from its domain).
RangeThe collection of all possible outputs the function can produce.

For f(x) = x² with inputs {1, 2, 3}, the domain is {1, 2, 3} and the range is {1, 4, 9}.

The one rule that defines a function: for a single value of x there must be only a single value of y. Multiple inputs can share the same output, but one input can never map to multiple outputs. (This is why the equation of a circle is not a function — in ML terms, it's described instead as a non-linear boundary.)

Try it: is this curve a function?

A curve passes the vertical line test — is a function — only if every vertical line crosses it at most once.

Limits and continuity

Functions come in two broad types: continuous functions, which can be drawn without lifting the pen from the paper, and discontinuous functions, which cannot.

Approaching from left and right

Take the discontinuous signum function — it outputs +1 for positive inputs, −1 for negative inputs, and 0 at exactly zero. Two new ideas come from inspecting its behaviour near x = 0:

  • Right-hand limit — the value the function approaches as x approaches 0 from the positive side. For signum, this tends to 1.
  • Left-hand limit — the value approached from the negative side. For signum, this tends to −1.

Continuous functions behave differently

For f(x) = x² at x = 3: as x approaches 3 from the positive side (e.g. x = 3.0000001), f(x) tends to 9.0000006 — essentially 9. Approaching from the negative side (e.g. x = 2.9999999) gives f(x) ≈ 8.9999994 — also essentially 9. Both sides agree.

Definition

A function is continuous at a point when: left-hand limit = right-hand limit = f(x) at that point. Approaching from either side must land on the same value. A function is continuous overall when this holds at every valid x.

Functions you'll meet again

A handful of functions recur constantly throughout machine learning and deep learning. For each, it's worth knowing its domain, its range, and whether it is continuous or discontinuous.

f(x) = ax + b
Domain: all real numbers. Range: all real numbers. Continuous everywhere — a straight line.
f(x) = x²
Domain: all real numbers. Range: y ≥ 0. Continuous and differentiable everywhere.
f(x) = |x|
Domain: all real numbers. Range: y ≥ 0. Continuous everywhere, but not differentiable at x = 0 (a sharp corner — no single tangent exists there).
Signum function
Outputs −1, 0, or +1. Domain: all real numbers. Range: {−1, 0, 1}. Discontinuous at x = 0 — left and right limits disagree.
f(x) = log(x)
Domain: x > 0 only (undefined for zero and negative numbers). Range: all real numbers. Continuous across its domain.
f(x) = eˣ
Domain: all real numbers. Range: y > 0. Continuous everywhere.
